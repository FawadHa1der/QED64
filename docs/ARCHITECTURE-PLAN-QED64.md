# QED64's side of the toolchain split: the implementation plan (2026-10-05)

Companion to docs/ARCHITECTURE-PROPOSAL-2026-10-05.md (decision 1 = A: the Lean fork owns the toolchain and publishes releases; QED64 = the library `qed64/embed`, the workers, the snapshot bake, the page). The user's brief for this side: simplify, remove duplication, make the code modular, make QED64 easy to use with or without the editor, remove or fix unused code, keep end-to-end tests green, and make build-from-source plus inclusion in another repo easy for anyone.

How it was made: a 28-agent mapping round over the repository at 84d594e (four lenses: consumer surface, duplication, dead code, build-from-source and end-to-end; every dead-code and duplication candidate re-verified by a skeptic, 11 items dropped or narrowed; facts in the owner's work/modular-facts.json), reconciled with the two consumers' own statements of 2026-10-05 (lean4game: imports only through `qed64/embed` on its qed64-dep branch; the showcase: submodule at 84d594e) and with the kernel session's script dispositions.

Standing rules for every step: commit on feature/modular-toolchain, stage by path; nothing a consumer imports or spawns disappears without a one-line shim and a CLI-CONTRACT changelog row; never `npm ci` or `npm install` on this host (node_modules is a symlink shared by every session; a lockfile change uses `npm install --package-lock-only`); the back-pressure session owns edit-coalescer.ts, resident-session.ts, params.ts, one line of main.ts, their tests, edit-storm.mjs, EMBEDDING §4/§7.8/§12, HARDENING #59 and TESTING.md until it lands on feature/embedding-api, which is then merged forward into this branch.

Gates. G0 (every step): `npx tsc --noEmit && npm test && npm run typecheck:site && npm run build:site && node pipeline/snapshot/cli.mjs --check-preludes && npm pack --dry-run --json`. G1 (end to end, under the host browser lock, against the served artifacts): `npm run test:adversarial` (preflight → compiler battery → e2e 23/23), plus the page lanes page-api, infoview-actions, liveness-faults, reload-storm (stock and embedded), edit-storm, and the integration tier with QED64_LEAN_ARTIFACT/QED64_INIT_SNAP. G2 (consumer): `npm run test:consumer` (tests/consumer/check-consumer.mjs): packs, resolves every exports key from the extracted tarball, and builds tests/consumer/fixture (qed64/embed page + qed64/edge Worker) with the repo's tsc and vite.
