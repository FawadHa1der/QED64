# QED64 architecture re-evaluation — 2026-09-02

*Produced by a 12-agent read-only review (five dimensions, one adversarial refuter per dimension, a completeness critic, and a synthesis), run while the full test pyramid executed; incident evidence from the same day. Appendix B lists every finding that survived refutation.*

## 1. Verdict

The system is bug-prone because the client (frontend/src/watchdog-shim.ts, 1088 lines, ~19 mutable flags, 11 timers) owns decisions that only the worker can make correctly — header resolution, environment choice, when the worker's document is in sync, and when a session is dead — and it encodes each decision as stored booleans with disjoint clear sites (F1, F5), timers standing in for signals (T8), and text regexes standing in for data (T7, F9, IU-4). Every incident today has that shape: a parser in a harness disagreed with the parser in the worker, a shim forwarded body edits against a document the worker did not have, a publish step landed in the loader the browser does not call, an export list pinned generated names, and an artifact tool overwrote the served tree because the only guard was a paragraph of prose. The pump transport's probe/replace/reboot lifecycle is the wrong shape (a header change is a session lifecycle event at the client) and the resident transport is the right shape but is currently held together by client-side substitutes for four worker guarantees that do not exist yet (bounded env allocation, cancellable header task, O(1) unresolvable-header verdict, non-blocking olean reads). The target is: one resident process for the page lifetime, worker-owned resolution reported as data, full-text document sync so divergence is impossible by construction, a five-state shim, and build/artifact invariants enforced by code — reached in ~9 phases that keep the shipped pump path green until the resident path passes the whole pyramid. Two things the plan must not promise: in-process exact-import environments (blocked by the WORKERFS-from-pthread stall and the no-free region rule, docs/UPSTREAM-NOTES.md:35-40) and environment eviction — exactness stays an explicit, rare, honestly-reported reboot.

## 2. Failure classes, ranked (bug_risk × ux_impact)

### C1. Worker document ≠ editor document (high × high)
Mechanism: the shim mirrors the worker's text byte-for-byte (applyContentChanges, watchdog-shim.ts:99-122, clamps silently at :111/:115) and decides per message whether to forward, hold, queue, or drop: header-changing didChange withheld (:896-915); body didChange during initial boot dropped and never replayed (:894→:915, F2); body didChange after a tag-2 hold forwarded to a pump worker still on the old header (:1010-1024→:1039, IU-2); resident body edits dropped while `residentUnsynced` (:890-893), a flag cleared at exactly one site (:875, F5); header keystroke in the liveness window forwarded raw to a worker that cannot change imports (:497-535, F3a).
Evidence: today's resident offset-divergence crash; e2e-resident delete-import-line-restore wedged 'elaborating'@120218 ms.
ONE change: advertise `textDocumentSync.change = 1` and always send `contentChanges:[{text}]` (Lean folds full changes, Server/Utils.lean:126-132; incremental reuse is diff-based, Language/Lean.lean:261/268). Track `workerVersion` = last version sent; on every Serving entry, if `workerVersion !== doc.version` send one full text. Deletes applyContentChanges, held-change merging, residentUnsynced, headerDiverged, three version-filtered replay loops (:502-510, :644-656, :945-955). Resolves conflict C1 in the critic's list: T4 wins over "incremental unrewritten" (IU-1), because the alias rewrite (:131-148) must ride the wire until KPS-4 lands.

### C3. Uncovered header = unbounded, uncancellable, stall-prone on-thread import (high × high)
Mechanism: 0031:144 bypasses the once-guard; a MISS falls to `processHeaderCore` (Language/Lean.lean:541-556) on the elaboration pthread; wasmEnvCache is append-only (0023:39-40); CompactedRegion.free is never sound (UPSTREAM-NOTES.md:35-40); the header task has `cancelTk? := none` (Language/Lean.lean:427/432) and importModules takes no token (critic C6); an absent module stalls on WORKERFS (HARDENING.md:189, shim :861-866). The 2 s debounce is a memory barrier, not UX (:847-852).
Evidence: per-keystroke header forwarding crashed the tab; 629-module import ~17 s (RESIDENT-WORKER-PLAN.md:56-61); e2e-resident import-char-by-char PAGE-CRASHED with per-keystroke MISSes.
ONE change (KPS-8): in resident mode the processHeader override never falls through — a header that is neither exact nor covered by a published env returns a HeaderProcessedSnapshot with one diagnostic ("modules X, Y are not loaded in this session — Load exact imports") and allocates nothing. Then env memory = the baked snapshots (bounded), resolution is a hash lookup on the elaboration thread with no FS touch, the WORKERFS stall class is gone, and the debounce can shrink to a transport coalescer. Cost (critic C7): headers not covered by a baked snapshot — `import Lean`, `import Std` — need their own snapshots baked, or the explicit reboot path; measure the Lean-env region beside the umbrella under the 6 GiB cap (qed64-boot.ts:156-158) before committing.

### C4. Death is the universal restart hub, fed by non-deaths (high × high)
Mechanism: `dispose()` transitions to 'dead' synchronously (client.ts:263-265) → onDead (qed64-boot.ts:143-144) → `handleWorkerDeath` (main.ts:226); every deliberate teardown re-enters and needs undo bookkeeping (`deathTimes = []` :333, `.pop()` :632, deathPending :560, resolvePendingDeath :685-691); the catch at :666-676 self-loops into the crash-loop breaker on tag-1/resident init failures (F4). The faithful reboot is triggered by a diagnostic regex (:320-338) that a user's own duplicate `def` satisfies, runs two full reboots plus an on-demand ~1 GB pack install via the `__qed64_remount__` sentinel (:754-760), and the alias guard regex lacks `/m` (:129, F9/IU-3). Resident `exit`/main-return is routed as a death too (lean.worker.js:825 → shim :269-276, critic A4).
Evidence: mathlib-name-shadow-faithful-switch killed the page in both gates (pump: `reading 'editor'` TypeError; resident: 540 s deadline, 2 page crashes).
ONE change: sessions get ids; the death listener is detached before dispose (detachSession exists, :308); the machine consumes `SessionDied(id)` and drops non-current ids; deliberate reboots are `Reboot(reason)` events that do not count toward the breaker. Faithful mode becomes an explicit user action ("Load exact imports") surfaced on the collision diagnostic, allowed only when the name is not declared twice in doc.text, executed as ONE reboot with honest pill text, never triggered by typing. Deletes deathPending, resolvePendingDeath, the dead-man switch (:1079-1085), the diagnostic-regex branch, the remount sentinel (pack install becomes part of that explicit action).

## 3. Target architecture

```
Monaco / lean4monaco client
   │ LSP over MessageChannel (full-text didChange, change=1)
   ▼
watchdog-shim.ts  (~200 lines: transport adapter + 5-state machine)
   │ typed LeanSession API only: boot / loadSnapshot / open / send
   │ events: onLsp, onHeaderStatus, onProgress, onTrace, onDead(id, code, reason)
   ▼
src/runtime/client.ts  (the ONLY port to the worker; knows the wire protocol; tracks only dead)
   ▼
public/workers/lean.worker.js  (one resident process per page: boot → loadSnapshot(.raw only) → open once → send via FIFO'd ring)
   │ stdout = LSP frames only; trace = structured events; exit surfaces = one dead{code,reason}
   ▼
Lean fork (FawadHa1der/lean4 @ KERNEL-PIN)  — processHeader override is the single resolver:
   exact key → cached env | covered by published snapshot env → ~40 ms | else header diagnostic, zero allocation
   emits $/qed64/headerStatus on every header setup; envs bounded to baked snapshots
```

Layer invariants:
- **Worker/kernel**: the document it holds is the last full text it received (no offsets); every header setup ends in exactly one `headerStatus` for that version; no environment is allocated for a header that is not covered; an unresolvable header never touches the FS from a pthread; the only ways to die are onAbort/onExit/worker error, each reported once with a code.
- **client.ts**: single owner of the port and wire protocol; no compiling/ready mirror (drops the client.ts:157 flip); `dispose()` never emits dead — it detaches first.
- **Shim state machine** — states: `Dead`, `Booting{sessionId, bootText}`, `Serving{sessionId, workerVersion, headerStatus}`, `Halted{reason: crashLoop}`, and during the pump era only `Probing{bootText}` and `Held{reason: unresolvable|hardFail, sessionId}`. Events: `DidOpen`, `DidChange`, `CoalesceFired`, `InitResult(sessionId, tag)`, `HeaderStatus(sessionId, version, status)`, `Progress(sessionId, n)`, `SessionDied(sessionId, code)`, `UserAction(exactImports|loadMathlib)`, `LivenessTimeout` (pump only), `Unload`. Rules: non-current sessionIds are dropped; in any non-Serving phase a DidChange only mutates `doc`; entering Serving with `workerVersion !== doc.version` sends one full text; the pill is `render(phase, reason, progress)`; the crash-loop breaker counts only `SessionDied` with a real code. Invariant testable per scenario: `hash(lastForwardedText) === hash(editorModel)`.
- **Boot/artifacts**: shell bound to `runtime-manifest.<buildId>.json` (already, qed64-boot.ts:51-54); pinned-manifest miss is a loud overlay error, not a fallthrough; every snapshot index entry carries `runtime`; the worker refuses unpaired pairs; the prefetch worker is the sole OPFS writer of `<key>.raw`; the Lean worker only sync-reads `.raw` into the heap (drops the .snapz cache, MEMFS staging, tee). Dev overrides (`?runtime=`, `?snapshots=`, `?resident=`) survive as dev-only, logged on the overlay, with the pairing check still enforced (critic C11).
- **Promotion**: producers write to work/staging/<buildId>/; public/ is additive-only with atomic manifest rename; `--gc` keeps chunks referenced by any manifest; CI/pre-commit asserts the default manifest's buildId has all chunks present.
- **Kernel series (~14 commits)**: exports generated at link; one resolution point; trace import; premise probe; pump entry points gone. Concern grouping per KPS-10, gated on the 0031 phase-1 blocker (PATCHES.md:241-243) clearing.

## 6. UX contract for import editing

| Gesture | What the user sees (target) | Mechanism |
|---|---|---|
| Typing an import char by char | Pill stays 'ready'; after ~150 ms the import line shows one grey diagnostic "module `Mathl…` not loaded"; body diagnostics remain; goals for the current text | Full-text didChange coalesced; worker refuses uncovered header in O(1) with zero allocation; headerStatus=unresolvable rendered inline; no probe, no hold |

## 7. Open risks and what would falsify the plan

- **R1 Env memory without eviction (critic C4).** The plan bounds envs to baked snapshots instead of evicting. Falsified if a required header set (e.g. `import Lean` + umbrella) cannot coexist under the 6 GiB cap — measure in phase 5 before deleting the fallthrough.
- **R2 Exact imports in-process (critic C5).** Deferred; exactness stays a reboot. The only in-process route consistent with the evidence is a host-served synchronous olean read ring (a second futex transport in io.cpp). Do not schedule it before phase 7.
- **R3 Header task cancellation (critic C6).** Not needed once uncovered headers never import; covered switches are ~40 ms. Falsified if body re-elaboration after a header change is itself long enough that keystroke-rate header edits pile up — `cancelRec` covers the body (Language/Lean.lean:486), so this should hold; verify with rapid-example-switch-storm in phase 6.
- **R4 Snapshot load concurrent with a live resident session (critic A5).** `_lean_wasm_load_snapshot_mem` blocks the runtime main thread for seconds and publishes into an array the elaboration thread reads (Shell.lean:245/307; Language/Lean.lean:512). Phase 6 must load only when fileProgress is drained and the worker acks idle, and publish must be atomic (swap a pointer, not mutate). Falsified if a load during a drained state still corrupts — then loads move to a dedicated boot-time step and 'Load Mathlib' becomes an explicit action.
- **R5 Resident exit and re-entry (critic A4).** `exit`/main-return currently reboots; the second `callMain` under EXIT_RUNTIME=1 is untested and bake-snapshot.mjs:47-50 records a wedge. Treat LSP `exit` as page-unload only; swallow it in the shim; test worker-kill separately.
- **R6 Pthread pool exhaustion (critic A6).** PTHREAD_POOL_SIZE=24 fixed at link; resident removes the pump's implicit serialization. Add a pool-occupancy trace event and a crash-gauntlet assertion in phase 5; falsified if storms exhaust it — then a shim-side concurrency cap on requests is needed (a small timer-free bound, not a lifecycle decision).
- **R7 Ring capacity vs full-text frames (critic C12).** 1 MiB ring vs full-text didChange of large buffers; phase 2 sizes the ring and keeps the completion ack. Falsified if the main thread's non-blocking polling cannot keep up — then chunk frames by version and let the worker drop stale versions.
- **R8 lean4game consumer** depends on coveringSnapshotFor, write-files, the pump tag-0 go-around and didOpen replacement. Phase 7 is blocked until its cypress suite passes on resident; nothing before phase 7 deletes what it uses.
- **R9 Served-runtime alias coverage.** Deleting the client alias rewrite assumes the served runtime has worker-side aliasOk in the pump probe (PATCH-BACKLOG #1 'coded, unbuilt'). Verify against the promoted buildId before phase 6, else keep the rewrite riding the full-text frame.
- **R10 infra/worker.js:13-16** serves any 16-hex path immutable, including per-build manifests; a wrong per-build manifest can never be corrected. Exclude `runtime-manifest.*.json` from the immutable rule in phase 1.
- **R11 Timings cited from mixed-version resident runs** (e2e-resident.log/-report.json were produced across hot-reloads). The mechanisms are verified in source; the numbers are not baselines. Phase 0's run-id reports make future numbers attributable.
