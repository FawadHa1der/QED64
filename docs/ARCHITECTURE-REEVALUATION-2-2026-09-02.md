## 1. What this pass concludes differently from the first review — and why

The first review's verdict stands: the client owns decisions only the worker can make. Its target architecture, however, was still shaped by the pump era in seven places, and two of its load-bearing mechanisms are wrong in the code. Each item below names the first-review claim, the evidence, and the replacement.

**1.1 The single resolver and `$/qed64/headerStatus` belong in `FileWorker.setupImports`, not in the `Language.Lean.processHeader` override (first review C2, phase 5; also Design 5's K2).**
`setupImports` has both `doc : DocumentMeta` and `chanOut` (pipeline/toolchain/work/lean4/src/Lean/Server/FileWorker.lean:390-395) and already emits a versioned notification from that site (`mkIleanHeaderSetupInfoNotification doc … isSetupError`, :424-425). `processHeader` has only `ctx` (Language/Lean.lean:500-504) — no document version, no output channel — and runs *after* `setupImports` returns (:506-508). A status emitted from the override cannot carry the document version; a status emitted from `setupImports` is serialized on the same channel as `publishDiagnostics` and `fileProgress` for that version (`mkLspOutputChannel`, FileWorker.lean:524-555). The 0031 lookup block (Language/Lean.lean:512-547) collapses to a one-line `match setup.prebuiltEnv? with | some env => … | none => processHeaderCore …`.

**1.2 The kernel stdout output ring (first review transport T1) is unnecessary; the "flush miss" is Emscripten's TTY newline buffering, fixable host-side — but not the way the winning design wrote it.**
The glue's stdout tty is `put_char(tty,val){if(val===null||val===10){out(UTF8ArrayToString(tty.output));tty.output=[]}…}` (verified in both `work/binsnap/bin/lean.js` and `pipeline/toolchain/work/build/stage1/bin/lean.js`): a frame body with no trailing `\n` sits in `tty.output` until the next write. That is UPSTREAM-NOTES #12, patch 0022's reason, the shim tickler (frontend/src/watchdog-shim.ts:316-324), the probe tickler (pipeline/snapshot/resident-probe.mjs:344-354) and the 15 s loss watchdog (:1100-1127) in one mechanism. Two things the winning design got wrong: (a) `FS.mkdev` over `/dev/stdout` in `preRun` cannot work — `initRuntime()` runs *after* preRun and calls `FS.init()` with no arguments, whose `createStandardStreams` does `FS.symlink("/dev/tty","/dev/stdout")` unconditionally (both glues), so a pre-existing `/dev/stdout` throws EEXIST at boot; (b) the named fallback `Module.stdout` has zero occurrences in the 48 MB glue. The hook that uses only exported FS API (`-sEXPORTED_RUNTIME_METHODS=…,FS,…`, patch 0031 CMake hunk line 50): in `onRuntimeInitialized` (public/workers/lean.worker.js:865, after `FS.init`) — `FS.close(FS.streams[1])`, `FS.registerDevice(major, {write(stream, buf, off, len, pos){…copy…; return len}})`, `FS.mkdev("/dev/stdout-qed64", major)`, `FS.open("/dev/stdout-qed64", "w")` (reuses the lowest free fd = 1). pthread `fd_write` is proxied to the main thread (`if(ENVIRONMENT_IS_PTHREAD)return proxyToMainThread(42,…)`, verified) and lands in that `write` op whole. The write op must dispatch on `lspMode` (frames → framer; otherwise → a `\n` splitter feeding `sink`), because `makeOutputCollector` (:696-724), the `[WASM INIT] i/n` sink (:1380-1386), the battery, the bakes and the exact-session warm compile all consume stdout *lines*.

**1.3 The pump does not "survive the storm"; the step-1 crash is a page death that predates the resident transport.**
`work/adversarial/gauntlet-pump-imports.log` reads `[11s] boot ready — storm begins` → `[12s] PAGE CRASHED`, `steps=1 crashed=true` — identical to both resident logs. Only the second pump run (`gauntlet-pump-imports2.log`, 72 steps) survived. The brief's framing ("pump survives only because each uncovered switch reboots") rests on that one run. The gesture is `importStormStep` blanking line 1 with `setValue` (tests/adversarial/crash-gauntlet.mjs:27-33) ~2 s after 'ready', i.e. a headerless (Init) full text into an umbrella-covered session while the first umbrella elaboration is running — the shim's own comment calls this "the known elaboration-wedge combination" (watchdog-shim.ts:622-624). A page crash is renderer death, not a wasm abort; `onAbort` and any heartbeat never see it. Consequence: deleting the 2 s debounce is gated on a Node reproduction (section 7, day 3), not assumed safe by K-ii.

**1.4 Exactness-as-reboot is the right shape, but every design that keeps it (including the winner) refuses its own header as written, because the fork has two environment registries.**
`getOrCreateWasmEnvFor` pushes to `wasmEnvCache` (Shell.lean:97) and never calls `Language.Lean.setPrebuiltHeaderEnvs`; the only publish sites are the two snapshot loaders (Shell.lean:245, :307) and `wasmLspInit` (:417, pump only). So a resident session whose header was warm-compiled on a fresh worker before `lsp-resident-init` (today's path: watchdog-shim.ts:631-634 → prepareHeader :816-817) MISSes in `prebuiltHeaderEnvs` and imports ~1.9k modules on the elaboration pthread — that is `mathlib-name-shadow-faithful-switch` settling `'elaborating'@420305ms` (work/adversarial/e2e-resident2-report.json). With K-ii (refuse on MISS) the same gesture becomes a refusal. Bug 5's class ("publish landed in the loader the browser does not call", HARDENING #30) is not "mitigated structurally" by any design that keeps two registries. Second grammar: the compile path keys by `Elab.headerToImports` (Shell.lean:123, Init included) while the resolver keys by `setup.imports` (FileWorker.lean:462 → Language/Lean.lean:513) with an `#[Init]` special case (:522) against an init bake keyed `#[Init, Init]` (docs/RESIDENT-WORKER-PLAN.md:59-60) — so "exact" is never reported for a warm-compiled key. Fix (section 2, K1): `prebuiltHeaderEnvs` becomes a read of `wasmEnvCache`; one key function.

**1.5 No snapshot load ever touches a live session (deletes first-review risk R4 and its phase-6 "worker asks the host to stream a snapshot while idle").**
`_lean_wasm_load_snapshot_mem` runs synchronously on the runtime main thread (lean.worker.js:1395) and publishes into the array the elaboration thread reads (Shell.lean:301-307 → Language/Lean.lean:512). Scheduling around that is a timer in disguise. The session's snapshot set is a boot input chosen from the initial text (main.ts:228 already boots `mathlib:true`; prepareHeader :795-796 loads the umbrella when the text wants Mathlib), and `loadSnapshot`/`compile` return `BAD_STATE` once the loop is open.

**1.6 Zero wall-clock coalescers on the page, not "a 150 ms coalescer after C3" (first review C9/IU-9).**
Monaco emits one didChange per `applyEdits`/`setValue`; the ring write is <1 ms; Lean's `cancelRec` on the previous header task (Language/Lean.lean:487) and per-command reuse (:614-675) are the debounce. Backpressure is a signal: ring occupancy (`residentPump` FIFO, lean.worker.js:161-188) and, if the pool measurement demands it, `PThread.unusedWorkers.length`. The winning design's 300 ms pill hysteresis is UI-only and never gates a message.

**1.7 One kernel rebuild, not two (first review phases 4 and 5; Design 5's A and B).**
Every rebuild is ~1 h + rebake, invalidates every returning visitor's content-addressed OPFS raw cache (HARDENING #25), and forces the lean4game workstream to re-vendor and rebake (its snapshots pair to `wasm64-303e5c765fc415ed`, pre-0031; `scripts/sync-qed64.sh` vendors 8 paths). The export generator is validated *offline* against the last build's `stage1/lib/temp` (no rebuild) and rides R1; pump-patch deletion is a series edit applied at whatever rebuild is next needed for another reason — never scheduled for hygiene.

**1.8 The harness cannot measure the target UX and passes one drill vacuously.**
`import-composition` waits for `/imports incomplete/` (tests/adversarial/e2e.mjs:182); the corpus settle regex is `/^ready$|imports (incomplete|failed)|keeps crashing/` (:244; crash-gauntlet.mjs:73); `unresolvable-import-composition` declares `containsMsgs:["imports incomplete"]` (corpus.json:1495) — a key e2e never reads (only settleMs/panicFree/mustSucceed/zeroErrors at :229-267). `editing-latency.mjs` waits up to 15 s for a *busy* label before waiting for ready (:33-34), so a 70 ms switch that never shows 'elaborating' reports ~15 000 ms. `worker-kill-recovery` records `recovered=true@4090ms` in every report with `minMs=4000` (:311) while a real reboot is ≥ 1.5 s settle + 10–12 s boot: `terminate()` fires no event, the pill never left 'ready', and the tickler posts into a dead worker forever. A `qed64.status()` tap lands on day 1 so the oracles never change again.

**1.9 Cheap deletions the first review missed (grafted from the Strangler).** The core pack is installed at every boot (qed64-boot.ts:64-79: 246 MiB first-visit download) although the init snapshot already covers Init and K1 refuses everything else; the resident session mounts library packs it must never read (mountPacks, lean.worker.js:614-654). After R1 the default session mounts no packs; packs exist only inside the exact-imports action.

**1.10 Endorsed unchanged:** first-review phases 0–1 (harness preflight, artifact discipline: `--out` staging default, no `rmSync` — promote-staging.mjs:45 still does `fs.rmSync(publicRuntime, …)`, bake-snapshot.mjs:124-127 still prunes inside `out`), C6/C8 mechanics, the UX rows on genuine crash and boot.

## 2. THE simplified architecture

### 2.1 Diagram in words

```
Monaco / lean4monaco (unchanged)
  │  LSP JSON-RPC over MessagePort; server capability textDocumentSync.change = 1 (full text)
  ▼
L3  frontend/src/lsp-relay.ts   (~150 lines, 3 states, 0 timers, 0 regexes)
  │  session.lsp(msg) / onLsp / onStatus / onDead(code)          [typed LeanSession API only]
  ▼
L2  src/runtime/client.ts        (the only owner of the Worker and wire protocol; tracks only `dead`)
  │  postMessage protocol 1: boot{config,files}, lsp{msg,replay?}, compile (pre-open only), telemetry, dispose
  │  events: progress, log, lsp{msg}, status{…}, heartbeat, ready, error{code,recoverable:false}
  ▼
L1  public/workers/lean.worker.js + lsp-front-door.js + lsp-frames.js
  │  boot → mount nothing (default) → load snapshots[] → [warmHeader compile] → mark preinit → ring → callMain(--worker)
  │  stdout = byte device (fd 1 reopened after FS.init): frames → strict Content-Length framer; lines → sink otherwise
  │  stdin = 4 MiB futex ring, FIFO pump, ack on completion
  ▼
L0  Lean fork @ KERNEL-PIN+R1 — FileWorker.setupImports is the ONLY header resolver:
     exact key → env | smallest covering published env (aliasOk) → env | else refuse (.error, zero allocation, no FS)
     emits $/qed64/headerStatus{version, mode, servedBy, moduleCount, missing, ms} once per header setup
```

### 2.2 Layer responsibilities and the exact messages/exports between them

**L0 kernel.** Inputs: ring frames (0031 io.cpp); boot-time exports `_lean_wasm_load_snapshot_mem` (the only browser loader), `_lean_wasm_compile` (exact sessions only, before `callMain`), `_lean_browser64_configure_input_ring`, `_lean_wasm_shell_mark_preinitialized`, `callMain(["--worker","-Dserver.reportDelayMs=0"])`. Outputs on fd 1 (frames only): upstream `$/lean/fileProgress`, `$/lean/ileanHeaderSetupInfo`, `textDocument/publishDiagnostics`, responses, plus NEW `$/qed64/headerStatus {version:Int, mode:"exact"|"covered"|"refused", servedBy?:Name (env key head, e.g. QED64.Essential | Init | <game module>), moduleCount?:Nat, missing?:[Name] (imports in no published closure), ms:Nat}`. fd 2 stays line text (`[WASM LSP] …`, `[WASM INIT] i/n`, `[DEBUG:PROGRESS]`).

Kernel change set R1 (one rebuild; anchors in the worktree):
- **K1 single resolver in `setupImports`**, inserted after the Emscripten guard bypass (FileWorker.lean:403-410) and *before* `setupFile` (:413 — `determineLakePath` + `pathExists`, SetupFile.lean:77-78, is a proxied stat per header on the elaboration pthread). `key := (collectImports stx).map (·.module)`, normalized by ONE function `Qed64.headerKey` shared with `wasmCompile` (Shell.lean:123) and the bakes (empty → `#[Init]`; `Init` de-duplicated so `#[Init, Init]` and `#[Init]` are the same key). Refuse first when any import carries `public`/`meta`/`all` in a non-`module` file (the battery's `header-meta-public-modifiers` errors are raised by header elaboration, which K-ii makes unreachable). Then `lookupPrebuiltEnv key` (exact | smallest covering, aliasOk moved verbatim from Language/Lean.lean:530-535, NameSet closures precomputed once per publish instead of `allImportedModuleNames.contains` per import). On `none` in worker mode on Emscripten: send `headerStatus{refused, missing}` via `chanOut.sync.send` (pattern :421) and `return .error {diagnostics := (← diagnosticsOfHeaderError "modules X, Y are not loaded in this session — Load exact imports"), result? := none, metaSnap := default}` (the shape at :439-444). On `some`: send `{exact|covered, servedBy, moduleCount, ms}` and return `.ok {…, prebuiltEnv? := some env}`. `SetupImportsResult` gains `prebuiltEnv? : Option Environment := none` (Language/Lean.lean:299-313); `processHeader` (:512-556) collapses to the match. Batch compiles (`lean_wasm_compile`, bakes, gate) are untouched: the refusal is gated on `Elab.inServer` (set at :456) ∧ `isEmscripten`.
- **K1b one registry.** `prebuiltHeaderEnvs`/`setPrebuiltHeaderEnvs` (Language/Lean.lean:243-248) are deleted; the lookup reads `wasmEnvCache` (Shell.lean:62) through a registered getter, so the cache push (:97, :241, :301) is the only publish. This is bug 5's class made unrepresentable and the exact-imports action made correct.
- **K3 (rider, ~15 lines, optional):** `ImportCompletion.collectAvailableImports` on Emscripten returns the union of published closures instead of walking the search path (FileWorker.lean:719-741 handler; no packs are mounted in a default session, so the walk is already over empty dirs — the rider only matters once packs exist in an exact session).
- **K4 exports generated in finish.sh** from `stage1/lib/temp/**/*.c` (whole-identifier scan, HARDENING #31) ∪ a ~40-line seed; validated offline first (day 3) against the tracked 104,665-line `src/emscripten-exports.txt`.
- **Kept:** `-Dserver.reportDelayMs=0` (a single-document playground has nothing to debounce across files; upstream's 200 ms would add 200 ms to every row in section 3 — FileWorker.lean:229). Dropped from the plan: K2 module index (the default session mounts no packs, so `metadata.files` would be empty; `unknown` vs `notLoaded` is affordance data derived in L4 from the manifest set import-completion.ts already fetches).
- **Not scheduled:** deletion of 0018/0023/0024(a)/0027 and the Shell.lean pump entry points (Shell.lean:332-437) is a series edit committed at S6 and built at the next rebuild that is needed for another reason.

Kernel/worker invariants:
- **K-i** verdict(header text) is a pure function for the session lifetime: no publish after the loop opens (L1 refuses `loadSnapshot`/`compile` after open with `BAD_STATE`, extending lean.worker.js:1209), so Lean's `unchanged`/`eqWithInfo` reuse (Language/Lean.lean:482-485) is sound.
- **K-ii** no environment is allocated after open: `Elab.processHeaderCore` is unreachable in worker mode on wasm; a refusal returns `.error` and allocates nothing.
- **K-iii** the header task touches no filesystem: K1 returns before `setupFile`; `findOLean` (Util/Path.lean:117-133) is never reached.
- **K-iv** `main` returns only on fatal error: L1 forwards only the five notifications FileWorker handles (FileWorker.lean:708-712; anything else is `throwServerError` :713 → `forceExit 1` :1114) plus requests; unknown requests are answered by the FileWorker itself (:766).
- **K-v** one death producer: `onAbort` (:902-912), `onExit` (:837 → `error{code:"WORKER_EXITED"}`), `unhandledrejection` (:343-358), worker `error` — each reported once behind a `died` latch; `dispose()` never emits.

**L1 worker host** (`lean.worker.js`; front door extracted to `public/workers/lsp-front-door.js` as a pure `step(state, frame) → {state, ringWrites, replies, statusDelta}` and the framer to `public/workers/lsp-frames.js`, both loaded by `importScripts` and by vitest via the `worker-internals.test.ts` vm pattern, and type-checked by a `checkJs` tsconfig that includes `public/workers`):

- (b) LSP front door: answers `initialize` (capabilities table moved from watchdog-shim.ts:30-63 with `change: 1`; vscode-languageclient honours `resolvedTextDocumentSync.change`, textSynchronization.js:24/:77; lean4monaco's dist contains no Incremental override), answers `shutdown` null, drops `exit`, forwards only requests + the five handled notifications, queues frames from script load until the loop is open (`boot` is the only state gate; dispatcher accepts `lsp` before `boot`), starts the loop on the first `didOpen`, converts a later `didOpen` into a full-text `didChange` with **version rebasing** (`base = lastVersion + 1 − newVersion`, added to outbound `textDocument.version`/`version` fields and subtracted inbound — `mkLspOutputChannel` drops notifications with `version < maxDocVersion`, FileWorker.lean:542-544, and `updateDocument` SETs it, :604; lean4game opens a fresh Monaco model per level so versions restart at 1), drops queued `didChange ≤ open version` only at loop start, and coalesces queued full-text didChanges by *arrival order* (newest wins) while the ring is full.
- (c) stdout byte device as in 1.2; framer = strict `Content-Length` state machine over a growable byte buffer that *copies* out of the HEAPU8 view (shared-memory growth leaves stale views, UPSTREAM-NOTES #16); `indexOfHeader` (:55-66) kept only as a counted resync; deletes the CR/LF skip (:105-111), orphan guard (:113-122), `lspChunkRing` (:52), `lsp-threads` (:1464-1479), and the per-chunk whole-buffer copy (:71-75).
- (d) ring 1 MiB → 4 MiB (:140); `lsp` is fire-and-forget; `residentSend`'s early ack (:242) goes away with the per-message result; `status.ring.bytesQueued` is the backpressure datum.
- (e) status from the frames it parses (:126): `{phase: booting|starting|elaborating|ready|headerRefused|dead, version, header: <last headerStatus>, ring, pool:{unused, running}}` — `ready` iff `fileProgress` drained for `version === lastSentVersion` and the last `headerStatus` for that setup is not `refused`; a body keystroke takes the `unchanged` path and emits no `headerStatus`, so `status.header` is per header setup, not per version.
- (f) heartbeat every 2 s once open; (g) conditional admission gate (section 6, attack 3): if the pool measurement shows exhaustion, do not write a didChange while `PThread.unusedWorkers.length < 4` — newest text wins, no timer.

### 2.3 Relay state machine (exhaustive; unit-testable with a FakeSession and no fake timers)

States: `Serving{session}`, `Rebooting{session, reason: crash|heartbeat|user|bootFailed}`, `Halted{deaths: number[]}`. Data outside the state: `initialize: JsonRpc|null`, `doc: {uri, languageId, version}|null`, `lastText: string`, `pending: Map<id, method>`, `deaths: number[]`, `stats {reboots, userRestarts, workerDeaths, breakerTrips, failedInFlight, staleDeaths}`.

| Event | In state | Transition |
|---|---|---|
| ClientMessage(msg) | Serving, Rebooting | record (initialize / doc fields / lastText / pending id) → `session.lsp(msg)` (a booting worker queues it) |
| ClientMessage(msg) | Halted | `msg.id` defined → respond `-32603 "checker halted"`; `didChange` → deaths=[], → Rebooting(user) with a fresh session |
| ServerMessage(session, msg) | any | dropped unless `session === current`; delete `pending[msg.id]` for responses; post to client |
| Status(session, s) | any | dropped unless current; forwarded to L4 |
| SessionDied(session, code) | Serving, Rebooting | dropped unless current (`stats.staleDeaths++`); failInFlight (`-32900` for `$/lean/rpc/*`, `-32603` otherwise, ≤1 ms); deaths = filter(>now−120 s)+[now]; ≥3 → Halted; else → Rebooting(crash): `session = makeSession()` (sync), attach, `boot()` after a 1.5 s settle inside the transition (heap release, today watchdog-shim.ts:618) |
| BootOk(session) | Rebooting | if current: `session.lsp(initialize, replay:true)`; `session.lsp(didOpen{uri, languageId, version: doc.version, text: lastText})` → Serving |
| BootFailed(session, err) | Rebooting | as SessionDied(session, "BOOT_FAILED") |
| RestartRequested(opts) | Serving | failInFlight("restarting with exact imports"); detach + dispose (no death event); `session = makeSession(opts)` → Rebooting(user); `stats.userRestarts++`, deaths untouched |
| Unload | any | `session.dispose()` |

Invariants asserted by `tests/unit/relay.test.ts`: `hash(fake.lastFullText) === hash(lastText)` after every scenario (edit-during-boot: DidOpen v1, DidChange v2, v3, BootOk → the open carries v3's text); zero client-facing messages synthesized except responses to failed in-flight ids; `setTimeout` spy = 0 calls in the relay module; a death carrying a stale session id changes nothing.

### 2.4 Worker front-door machine
`Loading(script)` → `Booting` → `Ready(loop closed, queue)` → `Open` → `Dead`. Per frame: `initialize` → answer (unless `replay`) + cache; `didOpen` while Ready → start loop (initialize + didOpen into the ring), drain queue; `didOpen` while Open → rebased full-text `didChange`; `shutdown` → answer null; `exit`, `initialized`, `$/setTrace`, `workspace/*`, `didClose`, and any notification not in the five → dropped and counted in `status.dropped`; everything else → ring FIFO; `didChange` while ring full → replace any queued didChange (arrival order). `loadSnapshot`/`compile` after Open → `BAD_STATE`.

## 8. What would falsify this design (measurable)

1. **Day-3 act 4 reproduces the step-1 crash as a wasm-level fault that K-ii does not fix** (e.g. shared-env mutation on header switch during a live elaboration). Then the worker adds "one header setup in flight, newest wins" (a signal-driven hold on `headerStatus`, no timer) until the fault is fixed in R1 — and section 3 rows 2–4 gain the duration of one in-flight setup (≤ ~70 ms covered).
2. **The fd-1 reopen after `FS.init` does not receive proxied pthread writes** (`nonFrameStdoutBytes` ≠ 0 or frames lost under a 4 MB diagnostics storm). Then the first review's kernel stdout ring returns as the transport for fd 1 — one more io.cpp hunk in R1.
3. **Pool measurement:** any 4-minute gauntlet sample with `status.pool.running > 20` or a session death coded from thread creation. Then the admission gate lands (a bound, not a timer), and if storms still abort, `PTHREAD_POOL_SIZE` is retuned at the next rebuild.
4. **Covered switch under 300 ms P50 is not reached** once the debounce is gone (editing-latency via the tap, three runs). Then the ~70 ms "real work" figure was not a floor and rows 3–4 are re-baselined — but the deletion itself stands unless (1) fires.
5. **Exact-imports memory:** umbrella 1.1 GB + an exact Mathlib closure region exceeds the 6 GiB cap or takes > 3 min on the essential pack (`lean_wasm_compile` of ~1.9k modules). Then the action's estimate says so, or exact sessions boot with `init` only and re-refuse other headers (a documented cliff), never silently.
6. **Heartbeat false positives:** any `SessionDied(heartbeat)` while `telemetry()` later answers. Then the probe window widens; the drill's `workerDeaths` delta makes it visible.
